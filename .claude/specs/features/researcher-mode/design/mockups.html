Researcher mode

Seven screens: the Builder | Researcher toggle, the Researcher grid of studies, a research doc and the strategy doc open in the drawer, the handoff cell in its states, the origin chip on handed-off Builder features, and the empty state. Every color, radius, type face and spacing value comes from ui/src/tokens.css (Obsidian Flux), and existing board classes are reused wherever they exist. Example content is a Spanish exam-prep (oposiciones) study, matching the owner's reference study.

Screen 1: the top bar toggle, Builder mode

The only change to Builder mode is a two-segment Builder | Researcher control in board__header, placed between the title block and board__meta. The header is already justify-content: space-between, so the toggle sits in the middle of the bar with no layout change. The grid, cells, gates and panel are unchanged.

Toggle

  • Look: a --surface-container-low track with a --card-border hairline and --radius-md. The active segment reuses the markdown toolbar's active state (--tb-active-bg fill, --primary text, a primary-tinted border), so it adds no new color. Each segment has a small mono glyph (▦ grid / ◎ lens) so the two modes look different at a glance.
  • Semantics: role="tablist" with two role="tab", using aria-selected. Left and Right arrows move between the segments. The visible focus ring is the board's standard 2px solid var(--primary).
  • State (Architecture Q9): the mode lives in the URL hash (#builder / #researcher) and is mirrored to localStorage["specmanager.mode"], with every read and write in try/catch. If storage is missing the board opens in Builder.
  • Meta: board__meta shows the count for the active mode only: "3 features" here, "3 studies" in Researcher.

Origin chip (preview, detailed in Screen 6)

Features created by a handoff carry a pill under the slug in the row label. It is a sibling of the existing Interview chip, and its hollow --primary ring means "reference material, not a status". Rows without origin (Syllabus picker) render exactly as they do today.

Screen 2: the Researcher grid

Researcher mode reuses the Builder grid's structure: grid, row__label, row__cell, and the 5.5rem card cap. A user who knows the Builder board reads it the same way. There is one row per study (PRD G2), and the columns follow the study's doc order: Market research · Concepts · User research · Marketing plan · Strategy · Handoff. Handoff takes the reserved right-hand track that Build uses in Builder mode, with the same --primary mono header, because it is the action column and not a document.

Study label and step rail (signature element)

  • Below the title and slug is the study's one-line idea (two-line clamp, --on-surface-variant).
  • The step rail has seven 4px segments in nextResearchStep order: market, concepts, plan, marketing, findings, strategy, handoff.
    • A done step fills with --primary.
    • The next step is a hollow --primary outline, the same "hollow = not yet" idea as the Interview chip ring.
    • A step with an outdated flag fills with --error.
    The caption names the next step, and the right side shows the count or the most urgent flag.
  • The next-step command appears as ▶ /specmanager-research <slug> <step>, styled like .card__build-exec. Click copies it to the clipboard. This is the PRD's "next-step command hint".
  • Done: a findings step counts as done when findings.length > 0 and newNotes is empty. A handoff step counts as done when at least one item is handed off.

Cells

  • Doc card: the DocCellView look, with title and vN. There is no status badge, because research docs have no draft or approved state (Architecture Q2). Concepts adds a ghost html kind tag.
  • "N new notes": an amber (--tertiary) tinted badge on the User research card, from newNotes(study). It clears once findings ingests those files.
  • "outdated": uses the same treatment as Builder's stale (--error border plus tinted badge), but the label says outdated. It means one or more dependsOn docs have a higher version than basedOn records. It never blocks anything.
  • Before findings: a User research doc with no findings yet shows a neutral 0 findings badge, so the user can tell the plan is drafted but nobody has been interviewed.
  • Empty cells: only the cell for nextStep gets card--ready (primary border plus full command). Other cells whose gate is open (Driving theory's user research and marketing) stay dashed and neutral with a short dim command, so one study shows one clear call to action.
  • Locked cells: these reuse card--locked, with the reason taken from checkResearchStep ("needs interview findings", "needs a strategy").

Handoff cell

The Handoff cell shows the parsed build list (parseBuildList), ranked. Items already handed off show a filled success dot and the feature slug in place of a checkbox. The cell opts out of the 5.5rem cap, like the walkthroughs stack, so the row grows and the doc cards stay pinned to the top. Screen 5 shows every state.

Live updates: when the user drops a file into notes/, the watcher emits file.changed, the board refetches /api/studies, and the amber badge appears. The pulse in board__meta shows the event, as it already does.

Screen 3: a research doc in the drawer

A click on any research card opens the existing DocPanel drawer with source="research". The drawer keeps its shell: 68% width, glass leading edge, Milkdown editor and toolbar, the 409 conflict banner, and the file path in the footer. Only what differs is listed below.

  • Crumb: <study title> › <kind label>. Meta reads <kind label> · vN.
  • Badges: a ghost research tag in the status slot, reusing .badge--interview ("a label, not a state"), then the id and generatedBy. The User research doc also shows the amber N new notes badge and a dim N notes ingested count (findings.length).
  • Actions: only Save and close. There is no Approve, Edit/Reopen or Gate? button (Architecture: research docs have no lifecycle). Save calls PUT /api/research/:id with baseVersion, and a version conflict shows the existing banner--warn reload flow.
  • New-notes banner: this is new, and appears only on User research while newNotes is non-empty. It uses banner--warn (amber) and lists the unread files by name, with the findings command on the right. The board never runs it. The user copies it into Claude.
  • Outdated banner: on any doc with outdatedUpstreams, this reuses the panel__stale block (Screen 4).
  • Missing scores: cells show the literal missing in mono italic --on-surface-variant (a td.miss style inside .prose). Scores are never invented (PRD success metric "findings fill"). Participants appear only as codes P1, P2 and so on.
  • Concepts: a click on the Concepts card opens the same drawer with the HTML rendered in the existing sandboxed iframe on --design-preview-bg, read-only, with no toolbar. That is identical to a design brief preview, so it has no separate mock.

Screen 4: the strategy doc

The strategy opens in the same drawer as the other research docs. Two things set it apart:

  • Outdated block: this reuses panel__stale and stale-list exactly, with links that jump to the other doc and the drift tag on the upstream that moved. The heading says "behind its sources" instead of "stale", and the block includes the synthesis command. It lists every dependsOn id, with basedOn against the current version, so the user can see which source moved: here, the two new interviews made User research v4.
  • The ## What to build ordered list is the handoff contract. It renders as an ordinary markdown <ol> with a bold title and an em-dash rationale per line, which is the format parseBuildList reads. The editor stays plain markdown: no inline checkboxes or widgets go inside the prose, because a builder would have to keep them in sync with Milkdown. Handoff happens in the grid's Handoff cell (Screen 5).

The header has a dim N features handed off badge, derived from the handedOff[] list that list_studies returns. It tells the user that edits here will set the "strategy updated" chip on those features.

If a manual edit leaves ## What to build with no ordered items, the drawer does not warn inline. The Handoff cell shows "no build items" instead (Screen 5, right column).

Screen 5: handoff, its action and its result

Handoff stays in the grid cell, so the user can compare the ranked list against the rest of the study, and so the board call (POST /api/studies/:id/handoff { itemIds }) has one obvious home. The command path (/specmanager-research <slug> handoff) calls the same handoffStudyItems, so both paths give the same result.

  • A, select: each item is a row with rank, checkbox and title. A checked row gets the --tb-active-bg tint. The button reads Create N features (btn--primary, the high-intent gradient) and is disabled at zero. No confirm dialog: the action is idempotent and only adds feature folders, which git can revert.
  • B, result: a success strip (--success on a 14% tint, matching banner--ok) says how many features were created and links to Builder mode (it switches the toggle to #builder). Handed-off rows change to a filled success dot plus the feature slug, which links into Builder and opens that row's PRD cell. The footer suggests the next command, /specmanager-prd <first slug>. The strip disappears on the next board reload, and the persisted state is the handed-off rows.
  • Skipped: when skipped[] is non-empty, a neutral strip names the existing feature. It is not an error.
  • C, gate closed: with no strategy, the cell is card--locked with the checkResearchStep reason. A strategy whose build list does not parse gets an error-tinted dashed border and names the exact heading to fix.

The handoff does not depend on whether the strategy is outdated. A user may hand off from an outdated strategy. The outdated badge on the Strategy cell (Screen 2), which sits right next to the Handoff cell, is the warning.

Screen 6: research origin on a Builder feature

Provenance is feature.json#origin and not dependsOn (Architecture Q7). It therefore appears on the row label (the feature) and never on the PRD card's status. It never affects gates or the stale badge.

  • Fresh: from <study title> · #rank in a .chip-origin pill. This is a sibling of .chip-interview, with the same pill, hairline, mono 0.66rem text and hollow --primary ring. It truncates with an ellipsis inside the 13rem label column.
  • Strategy updated: when the strategy's current version is greater than origin.strategyVersion, the chip switches to --error text, a filled ring and a faint error tint, and reads strategy updated · vA→vB. The study name moves into the tooltip. A filled ring means "something changed", the same filled-versus-hollow language as the existing chips. It is a computed signal, like stale, but it never cascades.
  • Interaction: hover shows a tooltip with the study, rank, strategy id and version. Click opens the strategy in the drawer (DocPanel source="research") without leaving Builder mode, so the user can read what changed next to the feature.
  • If a row has both an Interview chip (PRD cell) and an origin chip (label), both show. They sit in different columns and do not collide.

Screen 7: empty state

This is what the user sees the first time they flip to Researcher in a project with no research/ folder. It extends the existing .empty pattern (dashed --outline-variant border, --radius-md) into two panes, because this empty state has to explain a mode the user has never seen, not just name a command.

  • Left: a two-sentence explanation of the mode, the seven-step rail in its starting state (the same signature element as the study rows, with the first step hollow and next), and the command as a copyable .cmd block.
  • Right: the inline start form (PRD flow 2, Architecture POST /api/studies), with Study name and Idea or market. The slug preview runs the same slugify rule client-side for display only, and the server's uniqueSlug result wins. Submit (btn--primary) is disabled until both fields are non-empty. On success the WS reload replaces this view with the grid, and the new row's next-step hint reads … market.
  • Errors: on a 400, an inline --error line appears under the button, the same text treatment as .panel__error.
  • The focus ring on the active toggle segment shows the keyboard path. Tab lands on the toggle first, then on the form.
  • Market research is never started from the board. The board can create the study record, but drafting needs Claude in the session, because the plugin makes no model or web calls.

Open questions for the planner

  1. DESIGN.md is thin, but the tokens are real. The frontmatter in docs/DESIGN.md stores var(--…) references and only one type role. The real values live in ui/src/tokens.css, and every value here comes from that file, so no tokens were synthesized and bootstrap_design_tokens was not called. A sync_design_md refresh after ship should harvest the real hex, type roles and radii. Note that tokens.css sets --radius-lg to 16px, while DESIGN.md says 12px.
  2. No new color tokens. The new classes (.mode-toggle, .study-rail, .study__next, .badge--notes, .badge--outdated, .badge--kind, .card--handoff, .handoff-*, .chip-origin, .empty-research, .prose td.miss) use only existing tokens plus color-mix, in line with the tokens.css "no new hex" gate. .badge--outdated is visually identical to .badge--stale. Should the builder alias it rather than duplicate it?
  3. Amber for "new notes". --tertiary also means draft and in progress in Builder. Research docs have no draft status, so Researcher mode has no collision, but the meaning shifts between modes. Is that acceptable, or should "new notes" use --secondary?
  4. Step-rail data. The rail needs a per-step done/next/flag state. That can be derived client-side from list_studies (docs, outdated[], newNotes[], nextStep, handedOff[]), or the server can return a steps[] array. The planner should pick one, so the rail and nextResearchStep cannot disagree.
  5. "Strategy updated" data on the Builder payload. The origin chip needs the strategy's current version next to each feature's origin. Either /api/board joins the study data in, or the UI fetches /api/studies in Builder mode too. Architecture doesn't specify which.
  6. Origin chip click. Opening a research doc from Builder mode means DocPanel has to accept source="research" outside ResearchBoard. Confirm that is fine, or link to #researcher instead.
  7. Handoff from the drawer. v1 keeps handoff in the grid cell only. Should the strategy drawer also get a footer action (panel__footer--actions, "Hand off items…") that scrolls to the cell?
  8. Unsourced market research. The researcher writes an "Unsourced draft" notice into the body when it has no web search. Should the Market research card show an unsourced badge? That would need a computed field in list_studies, which Architecture does not include.
  9. Gate-open but not-next cells. This design shows them neutral with a short dim command (Driving theory's plan and marketing). Confirm it should not show three equally loud "Generate" cells.
  10. Responsive. The Researcher grid should follow the existing breakpoints in styles.css, with the Handoff cell wrapping below the row at tablet width as BUILD does. That was not mocked. Should the step rail collapse into its caption alone on mobile?
  11. Toggle counts. The segments carry no counts, and only board__meta shows the active mode's count. Should the inactive segment show a dot when that mode has activity, for example new notes arriving while the user is in Builder?
  12. Result strip lifetime. The "Created N features" strip is client state that a board reload clears. Should it persist until dismissed?
