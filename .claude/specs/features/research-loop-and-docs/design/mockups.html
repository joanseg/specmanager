Research loop and docs

Six screens that extend the Researcher board from design-researcher-mode-009. Concepts becomes a multi-doc Docs column, each study shows its brief, the brief and a Doc open in the drawer, the empty state points at /specmanager-research-loop, and the Docs column holds up at tablet width. Builder mode does not change. Every board color, radius, typeface and spacing value comes from ui/src/tokens.css, and existing classes are reused wherever they exist. The example content continues the earlier oposiciones and B2B tutor studies.

Screen 1: the Researcher grid with a Docs column

The grid keeps its structure from design-researcher-mode-009: one row per study, the 5.5rem card cap, and Handoff in the reserved right-hand track. Three things change: the Concepts column becomes Docs, the Docs cell holds a stack of Doc cards, and the study label gains a brief chip. Builder mode does not change at all.

Docs column

  • Header and track. The header reads Docs in --secondary (violet), the color Builder already uses for its Design stage, because Docs are the visual HTML artifacts. The track is wider than its neighbours (minmax(11.5rem, 1.35fr) against minmax(8.5rem, 1fr)) so a doc-type label and a one-line title fit. This replaces --grid-cols on .grid--research.
  • Stack. The cell renders every doc of kind doc as a compact .doc-card inside a .doc-stack (6px gap). The stack opts out of the 5.5rem cap, as the walkthroughs stack and the Handoff cell already do. The row grows, and the single-doc cards next to it stay pinned to the top.
  • Doc card (signature element). Each card has a 2px --secondary spine on its left edge, which marks it as an HTML Doc. The head line shows the doc type in mono uppercase --secondary 0.6rem, with vN on the right. Below it is the title, clamped to one line. The html kind badge is dropped inside this column because every Doc is HTML. It still shows in the drawer.
  • Doc type label. Presets map to Wireframes, Client presentation, Partner presentation, Investor deck and One-pager. A custom type shows its string verbatim in sentence case with a dim custom prefix, for example custom pilot proposal for HR leads, truncated with an ellipsis and with the full string in the tooltip.
  • Outdated. An outdated Doc gets the existing card--stale edge, an --error spine, and the ⚠ outdated badge on a third line. Here the investor deck recorded strategy v2 and the strategy is now v3. Following Architecture, any outdated Doc flags the rail's docs segment red.
  • Migrated wireframes. Oposiciones Spain's legacy concepts.html shows as a normal Wireframes card with its original title and the id concepts-oposiciones-spain (tooltip). It has no "legacy" badge, because nothing about it behaves differently.
  • Order. Cards follow listResearchDocs order: the legacy concepts.html first, then docs/*.html by file name. That is why One-pager comes before Wireframes in the B2B row.
  • Add another. When the study has at least one Doc and the docs step is open, a dashed .doc-add row closes the stack. Click copies /specmanager-research <slug> docs. The row stays dim, so the study's one loud call to action is still the next step (findings for B2B).
  • No Docs yet. The existing EmptyCell runs for step docs. When docs is nextStep (Driving theory) it shows card--ready, "Draft docs" and the full command. Screen 2 shows every cell state.
  • Click. Clicking a Doc card opens it read-only in the drawer (Screen 4).

Brief chip

  • The chip sits under the idea and above the rail. It is a pill that matches .chip-origin in size and type (mono 0.66rem, hairline, 999px radius).
  • Brief exists: a filled --primary page glyph, Brief and a dim vN. Click opens the brief in the drawer, where it can be edited (Screen 3). Hover brightens the border to --card-border-hover.
  • No brief (legacy studies, or studies started from the board form before any step ran): a dashed, transparent chip with a hollow glyph, reading no brief · … brief. Click copies /specmanager-research <slug> brief. It never turns red, because the brief gates nothing.
  • The brief is not on the rail. The rail stays seven segments: market, docs, plan, marketing, findings, strategy, handoff. A brief-less study's rail and nextStep are the same as before.

Screen 2: every state of the Docs cell

  • A, locked: gateFor("docs") needs market research. This reuses LockedCell, with the reason from checkResearchStep.
  • B, next: when nextStep === "docs", the cell shows card--ready with the label "Draft docs" and the full command. This is the only primary-bordered cell in the row.
  • C, open but not next: this can happen when a study skipped Docs and moved on. The cell is dashed and neutral with a dim … docs, the same rule as the other columns, so one study shows one call to action.
  • D, one Doc: one compact card plus the add row. The pair is about as tall as a normal 5.5rem cell, so a study with one Doc does not grow its row.
  • E, many Docs: every Doc shows, with no "+N more" collapse. Two wireframes Docs are allowed (Architecture Q5), and each shows on its own. Their slugs (wireframes, wireframes-2) are in the tooltip ids. The outdated card keeps its error edge wherever it sits in the stack.

Drawer header per doc type

  • Crumb: <study> › <doc-type label>. A preset uses its label. A custom type uses its string with the first letter capitalised.
  • Meta: <label> · vN. For a custom type, the meta reads Custom · vN so a long string is not repeated twice in the header.
  • Badges: the ghost research tag, then a new .badge--doctype (a --secondary outline that matches the column spine, lowercase type), then the id and generatedBy. The legacy doc keeps its concepts-<slug> id, and its crumb says Wireframes.
  • kindLabel grows a docTypeLabel(docType) helper so the column, crumb and meta all use one mapping.

Idea

An AI conversation coach that Spanish SMEs buy per seat, so staff who deal with export clients reach B2 English without booking live tutors.

Market

Spain, companies with 10–250 employees in export-led sectors: agrifood, industrial machinery, hospitality groups. Training is usually paid from FUNDAE credits.

Audience

  • Buyer: HR or People lead who owns the training budget.
  • Learner: sales, logistics and front-desk staff aged 25–50, at A2–B1 today, practising on their phone in short slots.

Goals

  • Learn whether HR leads would pay per seat for an app-only course.
  • Find the moments where staff need English most (calls, email, trade fairs).
  • Get to interview-ready wireframes and a pilot offer in two weeks.

Constraints

  • Solo founder; no live-tutor layer in v1.
  • Learner audio stays in the EU (GDPR).

Assumptions

  • Decided for you: app-based courses can be paid from FUNDAE credits. Unverified, so market research should check it.

Open questions

  • Is the first buyer the HR lead or the export manager?

Screen 3: the brief in the drawer

Clicking the brief chip opens ResearchDocPanel on brief-<slug>. The brief is markdown, so it gets the same Milkdown editor, toolbar, Save button and 409 conflict banner as the other markdown research docs. Nothing new is built for the editor.

  • Header: the crumb is <study> › Brief and the meta is Brief · vN. Badges are the ghost research tag, the id and generatedBy. The brief never gets an outdated badge, because its dependsOn is always empty.
  • Body: the seven pinned headings, in order: Idea, Market, Audience, Goals, Constraints, Assumptions, Open questions (INV-56f). Answers the user left to "decide for me" appear under Assumptions in italic --on-surface-variant. The board does not enforce the headings. The user may edit freely, and the loop's review pass checks their shape.
  • Save: PUT /api/research/:id with baseVersion, which is already wired for markdown research docs. The mockup shows the dirty state (Save enabled, caret in Goals).
  • Downstream hint: a dim right-aligned line in panel__footer says that saving marks the docs that read the brief as outdated. It is static text, not a computed list, so it needs no new data. After the save, the watcher reloads the grid and those cards show ⚠ outdated through the existing outdatedUpstreams.
  • The drawer is still 68% wide on desktop and full width under 640px, as today.

Screen 4: a Doc in the drawer

Any Doc card opens ResearchDocPanel, which now branches on isHtml (kind === "doc") instead of isConcepts. The body is the existing HtmlPreview: the sanitised HTML rendered verbatim in the sandboxed iframe on --design-preview-bg, the same as a design brief or the old concepts canvas. It has no toolbar.

  • Header: the crumb uses the doc-type label (Oposiciones Spain › Investor deck). The badges are research, .badge--doctype, the html kind tag, outdated if it applies, the id and generatedBy.
  • Read-only: the action button reads Read-only and is disabled. Today it says "Saved" for concepts, which suggests the doc could be edited. Docs are not edited in the board (PRD non-goal). They are redrafted with the docs step.
  • Outdated block: this reuses panel__stale and stale-list. Every dependsOn id is listed with based-on against now, and the one that moved carries the drift tag. The command is the docs step (stepCommand maps doc → docs). When the docs step runs, it offers "update this doc", so the user does not end up with a second deck.
  • Inside the iframe: the deck is the Doc's own HTML and styling: 16:9 slides stacked vertically, with figures carrying a source line and the unsourced one shown as n/a (unsourced). The board does not style it. Its colors are the agent's choice for the study's product, not board tokens.
  • Footer: the file path (docs/<doc-slug>.html, or concepts.html for a legacy doc), plus a dim reminder that the preview runs sandboxed with scripts off.

Screen 5: empty state

This is the existing two-pane .empty-research from EmptyResearch.tsx. The changes are in the copy and the commands, and the layout stays as it is.

  • Steps rail: STEPS reads market, docs, plan, marketing, findings, strategy, handoff. Screen 6: tablet layout

This follows the existing @media (max-width: 1024px) rules in styles.css. The label column drops to 10rem, the Handoff header hides, and .row__cell--build wraps below the row at full width. Docs adds one override to that breakpoint.

  • Docs track: it stays wider than its neighbours, at minmax(9rem, 1.3fr) against minmax(7rem, 1fr). It is about 9.5rem at 900px. Doc-type labels truncate with an ellipsis, and titles keep their one-line clamp. The tooltip carries the full type and title.
  • Add row: shortens to + add so it still fits on one line next to … docs.
  • Brief chip: stays in the label. The idea line and the next-step command hide at this width to save height. The rail caption still names the next step, and the chip keeps its click target.
  • Handoff strip: the wrapped Handoff cell lays its items out as a row of pills. This shows how the existing strip pattern applies to research rows. It is not new behaviour in this feature.
  • Mobile (<640px): not mocked, because the existing linearization applies. Each study becomes one column, so the Docs stack takes the full width and the type labels stop truncating.

Open questions for the planner

  1. DESIGN.md is thin, but the tokens are real. The frontmatter in docs/DESIGN.md holds var(--…) references and one placeholder type role. The real values live in ui/src/tokens.css, and every board value here comes from that file, so no tokens were synthesized and bootstrap_design_tokens was not called (same as design-researcher-mode-009).
  2. No new color tokens. The new classes (.doc-stack, .doc-card and its spine, .doc-card__type, .doc-add, .chip-brief, .badge--doctype, .grid__header--docs, .steps-bracket, .cmd--loop) use existing tokens plus color-mix only. Using --secondary for Docs reuses Builder's Design-stage accent for "visual HTML artifacts". Confirm that this cross-mode meaning is wanted, or use --primary.
  3. Iframe content colors. The deck in Screen 4 uses its own hex values (a teal accent, slate text). They are part of the Doc's HTML, which the researcher agent writes for the study's product, so they are outside the token system on purpose. Architecture open question 1 (a shared deck style per study) is still open and would decide where those values come from.
  4. Docs track width. This design widens the Docs column (1.35fr on desktop, 1.3fr on tablet), which slightly narrows the other doc columns. Confirm, or keep equal tracks and accept heavier truncation.
  5. Stack length. Every Doc shows, and the row grows (Screen 2 E). Should more than four Docs collapse into "+N more"? This design says no, because studies are expected to hold a few Docs each.
  6. Stack order. Cards follow listResearchDocs order (legacy first, then by file name). Ordering by doc type (wireframes first) or by most recently updated would read better, but it needs a sort rule in core or the UI. Pick one.
  7. Docs flag on the rail. Following Architecture, one outdated Doc turns the whole docs segment red, even when the study is otherwise complete (Oposiciones). Acceptable, or should an outdated deck not flag the rail?
  8. "Read-only" label. The HTML drawer button changes from "Saved" (disabled) to "Read-only" (disabled). This is a small copy change to the existing concepts behaviour. Confirm.
  9. Brief "used by" count. The brief drawer shows a static footer hint instead of "read by N docs", because StudyDocCard does not carry dependsOn. Add it to the study summary if a count is wanted.
  10. Custom type casing. Custom strings show verbatim in the column (lowercase as typed) and capitalised in the crumb. Should the docs step normalise the casing when it stores docType?
  11. Loop progress on the board. The loop writes docs one by one, and the board updates live through the watcher. No "loop running" indicator is designed, because the plugin does not track an in-flight loop. Confirm that none is wanted.
  12. Hidden idea line at tablet. Screen 6 hides .study__idea and .study__next under 1024px to keep rows short. Today they still show at tablet. Confirm the change, or keep them and accept taller rows.
